# Support

## Questions and how-to help

Use [GitHub Discussions](https://github.com/wfprieto/World-Class-SEO-Agent-System/discussions) for usage questions, implementation ideas, and general SEO workflow discussion. If Discussions is unavailable or a structured reproduction is more useful, use the [support request form](https://github.com/wfprieto/World-Class-SEO-Agent-System/issues/new?template=support_request.yml).

## Bugs and documentation problems

Open a GitHub issue using the appropriate issue form. Include the applicable operations control
ID, accountable owner or `Unassigned`, non-sensitive evidence, verification attempted, and a
rollback or containment position when the report concerns a change.

## Security issues

Do not include vulnerability details, credentials, client data, or exploit code in a public issue. Use the [private vulnerability report form](https://github.com/wfprieto/World-Class-SEO-Agent-System/security/advisories/new) and follow [SECURITY.md](SECURITY.md).

## Conduct concerns

Email private conduct concerns to [wfprieto@gmail.com](mailto:wfprieto@gmail.com). Do not publish
conduct reports, identifying details, or safety information in an issue, pull request, or
Discussion. The private vulnerability form is for security vulnerabilities and is not a
substitute for conduct reporting.

Operational intake and escalation procedures are documented in
[`docs/REPOSITORY-OPERATIONS.md`](docs/REPOSITORY-OPERATIONS.md#ops-security-intake).
The provider-verification contract and attestation requirements are documented in
[`docs/OPEN-ISSUE-REMEDIATION.md`](docs/OPEN-ISSUE-REMEDIATION.md#private-conduct-prerequisite).

The acknowledgement target is 72 hours. The monitoring role is the repository maintainer. The
confidentiality limits are need-to-know handling that cannot be absolute
when safety, law, or a fair investigation requires limited disclosure. The conflict handling rule: if the
report concerns the maintainer, state that conflict in the email subject; the maintainer must
preserve the report and seek a neutral external reviewer before deciding enforcement. Do not
include report contents, reporter identity, mailbox evidence, credentials, or private access links
in repository verification artifacts.
