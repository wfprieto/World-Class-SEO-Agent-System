# 20-Pass LibHunt Upgrade Review

Date: 2026-07-14

This review applies the 20-pass protocol to the LibHunt-inspired upgrade. The passes were performed internally as concrete improvement checks, then encoded through source governance, reference packs, tests, and validators.

## Pass Summary

1. Scope: limited sources to explicit value-bearing repositories.
2. Clean-room boundary: forbade copied code and copied external prose.
3. Source authority: separated primary search guidance from community checklist material.
4. Stack boundary: marked framework advice as advisory and implementation-scoped.
5. Evidence boundary: required rendered output and runtime data over component intent.
6. Determinism: promoted only testable rules into product-proof checks.
7. GEO/AEO: added observation contracts and AI visibility evidence requirements.
8. llms.txt guardrail: retained governance-only treatment where ranking impact is unproven.
9. Tool economics: added budget, quota, and credential gates to workflow prompts.
10. Link ethics: blocked metric-only outreach and manipulative link assumptions.
11. Crawl materiality: required scale and log evidence before declaring crawl-budget issues.
12. Checklist triage: labeled dated or unverified advice before rule promotion.
13. Sitemap scope: separated static, dynamic, large-site, image, video, and hreflang patterns.
14. Structured data: required eligibility and visible-content alignment.
15. Adapter resilience: required timeout, retry, URL safety, and structured missing-evidence states.
16. Orphan prevention: connected every new pack through `knowledge/reference-registry.json`.
17. Phase split correction: separated framework notes, adapter hardening, registry/cross-linking, and final rebaseline into explicit Phases 7-10.
18. Regression coverage: added tests for phase matrix, references, rules, workflow prompts, adapter hardening, and orphan detection.
19. Validation: used APIVR-style acceptance and verification gates for each phase.
20. Final audit: required all upgrade units through Phase 10 to be verified before completion.

## Result

The upgrade is complete when the full verification suite passes and `evaluation/libhunt-source-ingestion-matrix.json` marks every phase through Phase 10 as `verified`.
